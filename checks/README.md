## Запуск на PostgreSQL 16

Подключение — стандартные `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`
или `.pgpass`; пароль не помещать в команду/отчёт. Запуск из корня worktree D:

```bash
psql -X -v ON_ERROR_STOP=1 -f checks/00_synthetic.sql
psql -X -v ON_ERROR_STOP=1 -f checks/10_catalog.sql
```

Первый файл работает в отдельной пустой тестовой БД, второй требует модель.
Все объекты тестов временные, изменения откатываются. `assert_true` считает
ошибкой и FALSE, и NULL; `assert_numeric` сравнивает без допуска и округления.
Неожиданная ошибка завершает `psql` ненулевым кодом. Ожидаемые ошибки самого
assert перехватываются только в отрицательном контроле синтетического файла.

Это будущие команды: `scripts/build.sh`/`check.sh` ещё не существуют; их владелец A.

Сравнить строки raw в before/first/second отдельно; core/mart до первой сборки
могут отличаться/отсутствовать. После двух сборок snapshots должны совпасть
целиком, включая строки raw. Различие требует объяснения, а не удаления колонок.
Файл включает количество и MD5 мультимножества строк: порядок не влияет, дубли
сохраняются. Это удобный детектор изменений, не криптографическое доказательство;
при расхождении сравнить строки по ключам. На большом объёме сортировка хешей
