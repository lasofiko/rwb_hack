Правила v1:

- Текст переносится как есть: ID, статусы, города, ZIP и отзывы, включая пустые
  и пробельные тексты. Нет trim/lower/заполнения ZIP нулями.
- Типизированные поля: NULLIF(x, '') → pg_input_is_valid с буквальным типом →
  приведение; без округления денег, исправления дат или выдуманного пояса.
  Estimated delivery с ненулевым временем отклоняется, а не теряет время молча.
- Ключи integer канонизируются до проверки дублей; отклоняются все конфликтующие
  строки. Внутренний ключ сравнения отделён от source_key, который содержит
  исходные компоненты ключа через `|` (например, `o1|03`).
- reason содержит один детерминированный код из v1: null_key, duplicate_key,
  bad_type, null_required, invalid_value, orphan с суффиксами из контракта.
  payload = исходный to_jsonb(r), включая metadata. При нескольких проблемах
  сохраняется первая причина, строка изолируется ровно один раз.
- Нулевые платежи/рассрочки и not_defined сохраняются; отрицательная рассрочка
  отклоняется как invalid_value:payment_installments по новому CHECK v1.
- Строки raw.customers без представления в orders учитываются как orphan:orders;
  человек в core.customers — distinct customer_unique_id принятых адресных записей.
  Баланс raw.customers считается через core.orders + rejects.
- categories содержит переводы и дополнительные категории принятых products.
  Баланс справочника переводов считается по представленным строкам перевода,
  а не по полному числу categories (73 = 71 + 2 без перевода).
