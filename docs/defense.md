## Своими словами — D

Я проверяю не только совпадение итоговой выручки. Для каждого источника вычитаю
отклонённые копии по полному payload и сравниваю оставшиеся значения с core в обе
стороны. Поэтому одинаковый count не может скрыть замену или потерю строк.
Заказ, позиция, платёж и отзыв имеют разное зерно: до JOIN платежи и отзывы
сворачиваются до заказа, иначе деньги умножатся. Людей считаем по customer_unique_id,
адрес берём из конкретного заказа. У 789 review_id есть повторы, поэтому ключ
отзыва составной. У 8 delivered нет даты вручения: это сохранённая аномалия
источника, а не повод выдумать дату или выкинуть заказ.

## Что объяснить по вопросам

- Выручка — price позиций delivered; доставка отдельно. Чек — сумма price+freight
  сначала по заказу, затем среднее. Платёж не является выручкой продавца.
- Q4 — повторные оформления всех статусов за всю историю, а не только успешные покупки.
- NULL не равен нулю. Нет категории — отдельная unknown-группа на выводе; нет
  перевода — исходная категория сохраняется. В core выдуманной категории нет.
- Уникальные покупатели, средние и доли не складываются по срезам; итог пересчитывается.
- Календарь возвращает пустые месяцы. Доли округляются только при показе.
- ИИ предложил/подготовил проверки и документы; решения пользователя и фактические
  запуски записаны в docs/ai/d.md, без выдуманного утверждения итоговой модели.
