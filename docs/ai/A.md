# Использование ИИ — A

Пользователь поручил ИИ подготовить базовый коммит, контракт модели, DDL и воспроизводимую сборку, а затем интегрировать проверенные изменения остальных ролей. Дополнительные поручения: подключить ETL B, исправить сборку после перехода B на четыре файла и сделать порт PostgreSQL настраиваемым без фиксированного имени контейнера.

ИИ перенёс раздатку, подготовил структуру `raw → core → mart`, `model/10_ddl.sql`, транзакционную сборку и скрипты запуска проверок. По профилированию B ИИ актуализировал контракт: полная исходная строка в `etl_rejects`, явные причины отклонения, проверка типов через `pg_input_is_valid`, сохранение пробелов в текстах, ZIP без дополнения и четыре файла ETL B. Решения человека: продолжить работу после передачи B, направлять изменения через PR и принять исправление сборки после ревью. Согласование результатов, которого нет в истории проекта, не заявляется.

Подтверждено A: раздатка перенесена с зафиксированного коммита; после `setup.sh` в raw загружено 550 759 строк. Сборка дважды выполнялась успешно примерно за 19 секунд, отклонённых строк — 0, контрольные результаты Q1–Q5 совпали. После повторной сборки MD5 девяти таблиц совпали. Искусственная ошибка давала ненулевой код и откат core; обязательная ошибка проверки завершала `check.sh` с кодом 1, а известная аномалия оставалась отчётом. Тесты запросов C на временной пустой БД прошли.

При интеграции ИИ обнаружил несовместимость: B заменил единый `20_load_core.sql` файлами `20_1..20_4`, а сборка A продолжала обращаться к старому имени. Ошибка устранена: текущий `model/build.sql` последовательно запускает четыре файла B внутри одной транзакции. Правила контракта возвращены к версии с сохранением исходных пробелов; отличие от прежней загрузки затрагивало только пробельные тексты отзывов. Текущий контракт включён в корневой `README.md`, история использования ИИ сохранена в `docs/ai/A.md`.
