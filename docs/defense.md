## Рассказ на 3 минуты

1. Задача: объяснимо отвечать на вопросы Olist через raw → core → mart.
   Raw хранит источник; core задаёт типы, ключи и явную судьбу каждой строки;
   mart хранит удобное зерно для метрик.
2. Главное решение: заказ, позиция, платёж и отзыв имеют разное зерно.
   Их соединяем после агрегации, поэтому сумма не умножается.
3. Повторный покупатель — customer_unique_id; customer_id относится к записи
   заказа/клиента в источнике. Адрес сохраняем в контексте заказа.
4. Доказательство после интеграции: сверки raw/core/mart, сохранённые SQL/ответы C,
   чистая сборка, повторная сборка, неизменность raw и совпадение бизнес-результатов.
5. Ограничения: неизвестные категории и плохие типы учитываем явно;
   история snapshot ограничена; развитие — по измерениям, без нового UI в MVP.
