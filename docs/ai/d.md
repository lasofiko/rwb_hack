# Использование ИИ — D

Я поручила ИИ подготовить независимые проверки модели, документы для защиты и PR. Позже уточнила ограничения: не менять файлы A и использовать четыре файла загрузки B. Затем попросила остановить дальнейшие проверки и завершить письменные материалы.

ИИ подготовил SQL-проверки, синтетическую фикстуру, скрипт запуска и документы D. Я приняла решения сохранять полный payload с метаданными, строить календарь по всем датам заказа, оставлять тексты отзывов в исходном виде и направить PR в `main`. Согласование итоговой модели человеком не заявляю.

На PostgreSQL 16.14 подтверждены 11/11 синтетических проверок и успешная проба четырёх файлов B. Хеши SHA-256 и размеры восьми источников совпали; в полном raw — 550 759 строк. Первый сохранённый core прошёл 6 обязательных SQL-проверок, 3 отчёта и 2 baseline; пять таблиц результатов совпали с CSV команды C. Первый запуск клиента ранее достиг лимита 300 секунд, поэтому успешный код завершения сборки не подтверждён. Повторный прогон остановлен по моей просьбе; совпадение двух итоговых fingerprints не заявляется. Временный контейнер D остановлен, БД команды не менялась.

Ранее найденное обрезание пробелов в загрузке B устранено. Штатная сборка A всё ещё ссылается на удалённый `20_load_core.sql`, а контракт A описывает прежний интерфейс; файлы A не менялись. Полный тестовый драйвер и входные данные остались локально в игнорируемом `checks/local`. Подробный протокол приведён в `docs/defense.md`.
