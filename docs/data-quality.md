ETL по контракту v0 (main c8c7285):

- Файл B: `model/20_load_core.sql`, без BEGIN/COMMIT. A должен добавить
  `\ir 20_load_core.sql` непосредственно после `\ir 10_ddl.sql` в `model/build.sql`,
  до mart. Загрузка рассчитана на пустой core в транзакции сборки; повторно
  запускать её отдельно поверх непустого core нельзя. Пересборка даёт новый core.
- Входные строки сохраняются во временном staging. Типы и обязательность берутся
  из core DDL; известные типы проверяются отдельными pg_input_is_valid с буквальным
  именем типа. Это проверено в тесте со смешанными типами полей и плохими суммами.
- Числовые ключи нормализуются до integer перед проверкой дублей. При конфликте
  все строки ключа изолируются, произвольного победителя нет. UNIQUE customer_id
  заказа также проверяется. Для плохих типов/обязательных полей, nonfinite,
  отрицательных денег, оценок вне 1–5, сирот и неиспользованной записи покупателя
  в `core.etl_rejects` сохраняются исходный JSON, ключ и коды причин.
- `core.customers` содержит людей, адрес хранится в `core.orders`. Неиспользованные
  записи raw.customers учитываются как rejects; баланс raw.customers считается
  через адресные записи core.orders, а число людей — distinct принятых unique ID.
- `categories` включает справочник и исходные категории принятых products без
  перевода. NULL категории остаётся NULL; отсутствующий перевод — NULL английского
  имени. Баланс переводов проверяется по принятым строкам справочника, а не по
  полному числу categories (оно включает добавленные категории товаров).
- Города/ZIP сохраняются текстом без изменения регистра и дополнения ZIP нулями.
  Строковые поля trim; непустые тексты отзывов сохраняются дословно, полностью
  пустые/состоящие из пробелов превращаются в NULL. Нулевые суммы, installments=0,
  not_defined и аномальная хронология сохраняются. Estimated delivery с ненулевым
  временем изолируется как `non_midnight`, чтобы date не потеряла исходное время.
- Календарь охватывает дни от начала первого месяца покупки до конца последнего
  месяца любой даты заказов. При пустом принятом наборе заказов календарь пуст.
  После загрузки обязательный баланс всех 8 источников завершается исключением
  при несходимости. Ограничения DDL дополнительно проверяют PK/FK и домены.
