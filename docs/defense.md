## Рассказ на 3 минуты

1. Задача: объяснимо отвечать на вопросы Olist через raw → core → mart.
   Raw хранит источник; core задаёт типы, ключи и явную судьбу каждой строки;
   mart хранит удобное зерно для метрик.
2. Главное решение: заказ, позиция, платёж и отзыв имеют разное зерно.
   Их соединяем после агрегации, поэтому сумма не умножается.
3. Повторный покупатель — customer_unique_id; customer_id относится к записи
   заказа/клиента в источнике. Адрес сохраняем в контексте заказа.
4. Доказательство после интеграции: сверки raw/core/mart, сохранённые SQL/ответы C,
   чистая сборка, повторная сборка, неизменность raw и совпадение бизнес-результатов.
5. Ограничения: неизвестные категории и плохие типы учитываем явно;
   история snapshot ограничена; развитие — по измерениям, без нового UI в MVP.

## Вопросы и точные ответы

| Вопрос | Что показать/объяснить |
|---|---|
| Что означает строка каждой таблицы? | Контракт A: зерно, PK/FK, NULL; для review_id уникальность не предполагать |
| Почему не одна широкая таблица? | Синтетика: две позиции дают 30.30; два платежа × два отзыва превращают сумму в 121.20; предагрегация сохраняет 30.30 |
| Можно взять суммы платежей как выручку продавца? | Нет правила распределения: платёж относится ко всему заказу, продавцу принадлежат его позиции |
| Что такое средний чек? | Показать формулу C, состав суммы, валюту, статусы, даты и число уникальных заказов; не среднее цен позиций |
| Почему уникальные по штатам не складываются? | Один customer_unique_id может заказывать в разных штатах; итог пересчитывается |
| Чем NULL отличается от нуля? | Нет цены/платежа — нет известного значения, а не бесплатная позиция; полноту показываем отдельно |
| Почему есть месяц без продаж? | Календарь сохраняет месяц без заказов; пропуск дат не подменяет календарь |
| Как доказать отсутствие потерь? | Исходные строки = загруженные + изолированные; нет пересечения/пропусков; причины и lineage проверены |
| Что при расхождении с контрольной суммой? | Сверить популяции и JOIN, сохранить диагностику; числа из задания не подставлять |
| Какая реальная аномалия найдена? | Пока данных нет: ответ не подготовлен. После профиля B выбрать один подтверждённый случай и показать независимую сверку D |
