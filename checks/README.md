# Контракт проверок D

Актуализировано под main `2c4017f` и фактический ETL B (`52b20dc`).
Файлы A, включая `model/build.sql` и `docs/contract.md`, этим PR не меняются.

## Интерфейс модели

D использует DDL `model/10_ddl.sql` и четыре файла B строго в порядке:
`20_1_dims.sql` → `20_2_orders.sql` → `20_3_order_children.sql` → `20_4_calendar.sql`.
Тексты сохраняются как в raw; у чисел и дат — NULLIF(x, '') и явное приведение.
Зерно: orders/order_id, items/(order_id, order_item_id), payments/(order_id,
payment_sequential), reviews/(review_id, order_id). Люди — customer_unique_id,
адрес — в заказе. NULL-категория остаётся NULL; отсутствие перевода не удаляет товар.
Календарь покрывает месяцы первой и последней даты среди всех дат orders.

Карантин: одна исходная копия — одна строка etl_rejects; payload = полная raw-строка
с _source_file/_loaded_at. Проверяется принадлежность и кратность payload, словарь
причин B v1: null_key, duplicate_key, bad_type, null_required, invalid_value, orphan.
У причин с колонкой/родителем обязателен суффикс через ':'. При дублирующемся ключе
отклоняются все копии. source_key у B составляется через '|'; D не использует его
вместо payload для доказательства сохранности.

## Запуск и состав

После исправления подключения ETL владельцем A:

```bash
bash scripts/build.sh
bash scripts/check.sh
```

В проверенном main build.sql ещё ссылается на отсутствующий 20_load_core.sql;
нужны четыре подключения B. Это остаётся блокером A, а не исправлением этого PR.

check.sh запускает каждый файл отдельным psql с BEGIN/ROLLBACK и
`-X -q -v ON_ERROR_STOP=1`. SQL D не управляет транзакцией. Нарушение инварианта
вызывает RAISE EXCEPTION; runner возвращает ненулевой код при любой ошибке.

| Путь | Назначение |
|---|---|
| 00_synthetic.sql | Fanout, NULL, неизвестные категории, пустой месяц, повторные, чек, рассрочка, кратность копий |
| 10_catalog.sql | PostgreSQL 16, схемы, 10 таблиц core, валидированные ограничения |
| 20_keys_and_types.sql | Ключи/7 FK, деньги numeric без typmod, время без timezone, рассрочка ≥0 |
| 30_source_reconciliation.sql | Двусторонний EXCEPT ALL: raw минус rejects против core, включая адреса и тексты |
| 40_join_and_money.sql | Строки/суммы после JOIN измерений и предагрегированных фактов; конечные деньги |
| 50_calendar.sql | Границы/непрерывность/атрибуты дней и месячная ось |
| anomalies/*.sql | Только SELECT, агрегаты и ≤5 примеров на тип аномалии |
| baseline/*.sql | Отдельные ожидания фиксированной поставки, не ограничения будущих данных |
| lib/*.sql | Вспомогательные подключения, не запускаются отдельно |
| tools/snapshot.sql | Fingerprints всех полей raw/core/mart, без потери дублей и зависимости от порядка |

Платежи не обязаны равняться price+freight; даты могут нарушать бизнес-хронологию.
Эти свойства источников отражаются в отчётах, а не исправляются в данных.
Для проверки бизнес-повторяемости technical timestamps исключаются только явно;
в текущем core таких исключений нет. MD5 — детектор изменений, не криптографическое доказательство.

## Выполнено D

PostgreSQL 16.14, отдельный контейнер/БД без портов и volumes команды.
Синтетика 11/11 и `--probe-etl` с четырьмя файлами B — PASS.
На полном снимке проверены все 8 SHA-256, 550 759 raw-строк; прошли 6 обязательных
SQL, 3 отчёта и 2 baseline. Все пять результатов совпали с CSV C.
Первый клиент ранее достиг лимита 300 секунд; после подтверждения сохранённого
состояния модель проверена без перезагрузки raw. Повторный прогон остановлен по
просьбе пользователя: совпадение fingerprints двух сборок D не заявляется.
Подробный протокол — INTEGRATION.md и docs/defense.md.

## Синтетическое воспроизведение

Нужен отдельный PostgreSQL 16-контейнер с именем `rwb-d-quality-*`, репозиторий
смонтирован read-only в /work, создана пустая БД d_checks_fixture.

```bash
python checks/tools/smoke_checks.py --container CONTAINER_NAME
python checks/tools/smoke_checks.py --container CONTAINER_NAME --probe-etl
```

Оба вызова теперь должны завершиться кодом 0. Guard запрещает другую/непустую БД,
каждый сценарий откатывается. Фикстуры не смешиваются со штатным raw команды.
Полные источники, временные логи и черновой локальный драйвер находятся в
игнорируемом checks/local/ и в PR не входят.
