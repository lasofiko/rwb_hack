# Концепция дашборда

Статус: проект D. Интерфейс не требуется. Имена физических таблиц/полей появятся
из контракта A, окончательные формулы — из `docs/metrics.md` C.

Пользователь — руководитель маркетплейса. Решения: где меняется объём продаж,
какие продавцы/категории дают вклад, насколько возвращаются покупатели.
На каждом экране видны период, временное поле, статусы, валюта, дата загрузки
и предупреждение о неполных данных. Конкретная валюта ещё не подтверждена.

| Блок / решение | Формула для согласования с C | Зерно / нужные поля контракта |
|---|---|---|
| Динамика / найти спад | Сумма стоимости позиций в выбранной популяции; доставка отдельно до решения C | Календарь month; заказ order_id, purchased_at, status; позиция order_id, price, freight |
| Продавцы / вклад | Сумма стоимости только позиций продавца; доля = сумма продавца / сумма всех в явно указанном срезе | Позиция order_id + order_item_id, seller_id, price; продавец seller_id |
| Категории / ассортимент | Сумма позиций по категории, включая unknown; доставка отдельно | Позиция product_id, price; продукт product_id, category; перевод category, label/status |
| Средний чек / размер покупки | Сумма суммы заказа / count(DISTINCT order_id) той же популяции; состав суммы определяет C | Предагрегированный заказ order_id, сумма, статус и дата; платежи отдельным фактом |
| Повторные / удержание | 100 × покупатели с ≥2 заказами / покупатели с ≥1 заказом в определённом C окне | Заказ order_id, customer_id; связка customer_id → customer_unique_id |
| Качество / доверие | Изолированные строки по источнику/причине; unknown; заказы без нужной даты/цены | Lineage, карантин, counts; окончательный интерфейс A/B |

Период фильтруется по согласованной дате заказа, не по дате загрузки.
Месяцы без фактов показываются через календарь с 0 заказов. Отсутствие цены
не превращается в нулевую цену; рядом нужна полнота суммы. Категория без перевода
сохраняется с исходным названием и отметкой, отсутствующая категория — unknown.

Срезы: период, статус, продавец, категория, штат адреса заказа. Географию продавца
и адрес покупателя не смешивать. Фильтр по продавцу/категории меняет популяцию
заказов: заказ учитывается один раз в чеке и повторных, даже если содержит
несколько подходящих позиций. Как именно фильтруется сумма чека, согласует C;
до этого смешанный KPI не публиковать. Для повторных отдельно подписать:
«два заказа внутри периода» или «вернулся с учётом всей истории».

Сумма позиций аддитивна по взаимоисключающим категориям/продавцам. Платёж всего
заказа нельзя распределять между продавцами без отдельного правила. Число заказов
по категориям, уникальные покупатели и повторные неаддитивны; средние и доли
пересчитываются из исходных числителей/знаменателей после фильтра. Отзывы и платежи
агрегируются до соединения с заказом. Показатели качества не прятать в бизнес-KPI.

Приёмка: календарь полный; сумма категорий с unknown совпадает с общей на одной
популяции; итоговые доли пересчитаны; несколько платежей/отзывов не меняют выручку;
все графики объясняются сохранёнными SQL C. Сейчас эти проверки не запускались.
