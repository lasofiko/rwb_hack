# Решения модели — проект до контракта v1

Основа — контракт v0 A из PR #4; ETL и результаты ещё не проверены D.

| Выбор | Альтернатива | Причина |
|---|---|---|
| Неизменяемый raw → типизированный core → mart нужного зерна | Очистка raw на месте | Аудит, объяснение потерь и воспроизводимость |
| Отдельные факты позиций, платежей и отзывов; JOIN после агрегации | Общая плоская таблица | Связи 1:N иначе умножают деньги и строки |
| Покупатель по customer_unique_id, адрес в контексте заказа | Группировка по customer_id, последний адрес | Нужны повторные покупки и достоверная история |
| numeric без typmod; NULL в core, unknown в mart; карантин | float, NULL→0, молчаливый INNER JOIN | Точные суммы и объяснимый баланс строк |
| Календарная ось, пересчёт долей/средних/уникальных | Только месяцы с фактами, сумма готовых KPI | Пустой месяц и корректные итоговые показатели |
| PostgreSQL 16 и повторяемая SQL-сборка | Новый оркестратор/облако в MVP | Меньше зависимостей, проще проверить и защитить |

Ключ отзыва v0 — (review_id, order_id); отдельные поля не уникальны. Пользователь
подтвердил полный raw payload карантина с метаданными и календарь до максимума
всех дат заказа. Эти уточнения передаются A для контракта; неполные суммы открыты.
По решению пользователя тексты отзывов сохраняются точно, включая пробелы;
общий btrim для них не применяется. Даты/расхождения платежей не исправляются молча.
Предложение C v0: выручка sum(price), чек sum(price + freight_value), продажи
delivered, Q4 все статусы/вся история, BRL. Это ещё не проверено. Записку D уточнит
после v1 и ETL; утверждение бизнес-формул и результаты запусков не заявляются.
