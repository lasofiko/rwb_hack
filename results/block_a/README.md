`verification.json` содержит проверки, числа строк core и SHA-256 SQL.
Отклонённых строк в этом прогоне нет. Это не независимая проверка D.
Q3 включает доставку, товарная выручка Q1/Q2/Q5 — только цену товаров.
Повторный покупатель Q4 — человек с ≥2 оформлениями, все статусы.
В CSV пустой `category_key` означает NULL, подпись такой группы — `unknown`.

## Что осталось для окончательного результата

1. A подключает файл B к общей сборке: `\ir 20_load_core.sql` после DDL.
2. A/B согласуют расхождения с v1: `btrim` строк и преобразование пробельных
   отзывов в NULL, а также другой набор/формат кодов причин в rejects.
3. C повторяет штатную сборку из main и сверяет эти CSV. После этого статус
   предварительного прогона снимается, фиксируется точный commit сборки.

Команда экспорта одного ответа после готовности штатной сборки:

```bash
docker compose exec -T postgres psql -X -q -v ON_ERROR_STOP=1 --csv \
  -U hack -d marketplace -f /work/queries/01_monthly_revenue.sql
```
